# Reward System (리워드 시스템)

> **Phase:** 1.4
> **참조 에이전트:** Architect (모델/로직), Artisan (UI/애니메이션), Bridge (트리거 서비스)
> **선행 조건:** Phase 1.0 (재고 관리) + Phase 1.1 (AI 레시피 추천) 완료
> **상위 문서:** `roadmap.md §6`

---

## 1. Feature Summary

요리 활동(재고 등록, 레시피 완료, 연속 사용 등)에 보상을 부여하여 사용자의 지속적인 사용 동기를 부여하고, "요리가 즐거운 창작"이라는 브랜드 가치를 강화하는 시스템.

**핵심 철학:** 보상은 '강요'가 아닌 '발견의 기쁨'. 윕업 톤(따뜻함·즐거움·잔소리 금지)을 철저히 유지.

---

## 2. User Stories

### US-1: 업적 달성
> "첫 레시피를 완료했더니 '첫 요리사' 뱃지를 받았다!"

- **Given:** 사용자가 레시피 조리를 완료 표시
- **When:** 업적 조건이 충족됨
- **Then:** 축하 Lottie + `HapticFeedback.mediumImpact()` + 업적 카드 팝업
- **And:** 리워드 대시보드에 뱃지 추가

### US-2: 연속 기록
> "3일 연속 요리를 기록했다."

- **Given:** 사용자가 매일 최소 1개 레시피를 완료 표시
- **When:** 연속 일수가 마일스톤(3, 7, 14, 30일)에 도달
- **Then:** 연속 기록 축하 + 특별 뱃지

### US-3: 리워드 대시보드
> "내가 모은 뱃지와 활동 기록을 보고 싶다."

- **Given:** 사용자가 리워드 화면에 진입
- **When:** 화면 로드
- **Then:** 획득 뱃지 목록 + 활동 통계 + 연속 기록 표시

## 3. Reward Types

### 3.1. 업적 (Achievement)

| ID | 이름 | 조건 | 이모지 |
|----|------|------|--------|
| `first_stock` | 첫 재료 등록 | StockItem 1개 이상 등록 | 🥬 |
| `first_recipe` | 첫 요리사 | 레시피 완료 1회 | 👨‍🍳 |
| `recipe_5` | 요리 입문자 | 레시피 완료 5회 | 🍳 |
| `recipe_20` | 요리 매니아 | 레시피 완료 20회 | 🔥 |
| `streak_3` | 3일 연속 | 3일 연속 요리 | ⭐ |
| `streak_7` | 일주일 연속 | 7일 연속 요리 | 🌟 |
| `streak_30` | 한 달 연속 | 30일 연속 요리 | 🏆 |
| `explorer` | 탐험가 | 5개 이상 recipe_type 시도 | 🗺️ |
| `zero_waste` | 제로 웨이스트 | 유통기한 초과 재료 0개 유지 7일 | 🌱 |
| `column_reader` | 호기심 독자 | 칼럼 5편 이상 읽기 (Phase 2.6) | 📚 |

### 3.2. 활동 통계

| 지표 | 설명 |
|------|------|
| 총 요리 횟수 | 완료 표시된 레시피 누적 수 |
| 연속 요리 일수 | 현재 연속 기록 |
| 최장 연속 기록 | 역대 최장 연속 일수 |
| 시도한 recipe_type | 고유 recipe_type 종류 수 |
| 등록한 재료 수 | 누적 등록 재료 수 |

## 4. Data Requirements

### 4.1. Achievement 모델

| Field | Type | 설명 |
|-------|------|------|
| `id` | String | 업적 고유 ID |
| `title` | String | 업적 이름 |
| `description` | String | 달성 조건 설명 |
| `emoji` | String | 대표 이모지 |
| `unlockedAt` | DateTime? | 달성 시각 (null이면 미달성) |
| `condition` | AchievementCondition | 달성 조건 (타입+임계값) |

### 4.2. UserRewardStats 모델

| Field | Type | 설명 |
|-------|------|------|
| `totalRecipesCompleted` | int | 총 요리 횟수 |
| `currentStreak` | int | 현재 연속 일수 |
| `longestStreak` | int | 최장 연속 기록 |
| `uniqueRecipeTypes` | Set\<RecipeType\> | 시도한 레시피 타입 |
| `totalStocksAdded` | int | 누적 등록 재료 수 |
| `lastActivityDate` | DateTime? | 마지막 활동 일자 |

### 4.3. Isar 저장

- `AchievementCollection`: 업적 상태 영속화
- `UserRewardStatsCollection`: 활동 통계 영속화

│ 📊 활동 통계                   │

### 5.2. 업적 달성 팝업

- 화면 중앙 모달 (또는 바텀시트)
- Lottie 축하 애니메이션 (`success.json` 변형)
- 업적 이모지 + 이름 + 설명
- [확인] 버튼으로 닫기
- `HapticFeedback.mediumImpact()`

### 5.3. 디자인 톤

| DO | DON'T |
|----|-------|
| "축하해요! 첫 요리를 완성했어요" | "미션을 완료하세요" |
| "멋진 기록이에요!" | "보상을 받으려면 매일 요리하세요" |
| 자연스러운 발견의 기쁨 | 강압적 알림, 진행률 압박 |

## 6. Trigger Logic

### 6.1. 업적 체크 시점

| 이벤트 | 체크할 업적 |
|--------|-----------|
| `StockItem` 추가 | `first_stock` |
| 레시피 완료 표시 | `first_recipe`, `recipe_5`, `recipe_20`, `explorer` |
| 앱 진입 (일별 1회) | `streak_*`, `zero_waste` |
| 칼럼 읽기 완료 | `column_reader` (Phase 2.6) |

### 6.2. 연속 기록 계산

- 기준: `lastActivityDate`와 오늘의 차이
- 어제 활동 있음 → `currentStreak += 1`
- 어제 활동 없음 → `currentStreak = 0` (오늘 활동 시 1로 리셋)
- `currentStreak > longestStreak` → `longestStreak` 갱신

## 7. Edge Cases

| 상황 | 처리 |
|------|------|
| 앱 삭제 후 재설치 | 로컬 데이터 초기화 (Phase 2.0+ 서버 동기화로 복원) |
| 날짜 변경선 (자정) | UTC 기준 날짜로 계산 |
| 같은 업적 중복 달성 | `unlockedAt`이 이미 존재하면 무시 |
| 오프라인 상태 | 모든 로직 로컬 처리 (Phase 2.0+ 서버 동기화) |
